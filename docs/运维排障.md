# 运维排障

按「现象 → 原因 → 处理」组织；条目全部来自真实日志与实测踩坑。
通用第一步永远是：**看日志**（见文末「日志在哪看」）。

## 一、启动与基础设施（MySQL / Redis / 队列）

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 MySQL `1045 Access denied (using password: NO/YES)` | `.env` 的 `MYSQL_USER/PASSWORD` 不对或没配 | 核对 `.env` 的 `MYSQL_*` 参数，改完重启 |
| 启动报 Redis `Connection refused 127.0.0.1:6379` | Redis 服务没启动 | `net start Redis`（服务名见 `sc qc Redis`），确认 `redis-cli ping` 返回 PONG |
| 提交任务返回 503「任务队列不可用」 | Redis 未连接或版本过老 | 先按上一条确认服务；再看 app.log 里的具体 Redis 错误 |
| app.log 报 `wrong number of arguments for 'hset' command` | **Redis < 4.0 太老**：RQ 3.0 用到 HSET 变长参数（4.0+ 才支持） | 升级 Redis ≥ 4.0（Windows 推荐 5.0.14 tporadowski 版，装为同名服务），见部署手册 |
| 任务一直 pending，`worker_console.log` 只有初始化行 | worker 未消费：连接死锁/崩溃静默（历史版本缺陷） | 更新到最新代码；手动 `python -m service.worker_main` 前台复现看报错 |
| 任务执行中，`worker_console.log` 有 rq 报错堆栈 | worker 进程内 job 执行异常 | 按堆栈定位；worker 由 Web 自动重启（连续崩溃 5 次后停止，见 app.log） |
| `tasklist` 里残留 `python -m service.worker_main` 孤儿进程 | Web 被强杀（任务管理器结束/断电）时子进程未随退 | 结束该进程即可，或忽略（不占端口，仅与新 worker 并发消费同一队列，任务状态机有 CAS 保护不会重复执行） |

## 二、任务对账阶段

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务失败，错误「原始文件不存在：…\xxx.csv」（步骤1） | 上传缺文件，或 `data/sample/` 被删 | 重新上传 5 份 CSV；示例缺失则确认 `后台数据/` 在不在，重启会自动回拷 |
| 任务失败，错误「原始文件 xxx 为空」 | 源 CSV 是空表 | 检查后台导出是否选错了时间范围 |
| 上传被拒「无法识别的文件」 | 文件名缺关键字 | 文件名需含「亚马逊/Temu/收款」+「订单/结算/流水」组合 |
| 上传被拒「重复上传」 | 两份文件识别为同一类型 | 删掉多余文件 |
| 任务卡「执行中」不动 | 极端场景进程假死 | 无需等待：15 分钟看门狗自动置失败；刷新页面有僵尸 running 兜底立即判失败 |
| 任务失败「执行超时（超过15分钟）」 | 单任务超 15 分钟（通常 AI 批量归因网络极慢） | 查 run.log 定位步骤；网络恢复后重跑 |

## 三、AI 归因（千问）

| 现象 | 原因 | 处理 |
|---|---|---|
| 备注列全是「AI分析失败:API返回错误码:403,Free quota…」 | 百炼免费额度用尽 | 控制台充值或换 key 写入 `.env` 的 `DASHSCOPE_API_KEY`，重启 |
| 备注列出现「AI服务已熔断，跳过分析」 | 连续 3 次失败自动熔断（保护性跳过剩余行） | 与上一条同源；恢复后**新开任务**自动恢复（熔断器按任务重置） |
| 页面提示「未配置 AI Key，本次未归因」（琥珀色） | `.env` 没配 key 或服务启动时 key 未生效 | 配置 `.env` 后**重启服务**（配置在启动时读取） |
| 日志 `429 Requests rate limit exceeded` | 触发模型限流 | 等几分钟重跑；频繁发生则查百炼控制台限额 |
| 调用报 `403` 但 key 看似正常 | 模型名无权限/无额度 | 核对 `engine/config.py` 的 `QWEN_MODEL` 是否在百炼控制台可用 |

> 降级原则：AI 全程失败也不影响对账——任务照常 success，只是备注列降级。

## 四、聊天面板（FastGPT）

| 现象 | 原因 | 处理 |
|---|---|---|
| 结果页没有「Agent 问答」聊天框 | FastGPT 三项配置不齐 | `.env` 配齐 `FASTGPT_BASE_URL/API_KEY/APP_ID` 后重启（启动 WARNING 有提示） |
| 回复「AI服务暂不可用」 | 上游超时/500/网络不通/未配置 | 看 app.log 的「聊天代理失败」堆栈；常见为网络或上游慢（超时 180s） |
| 回复很慢（30~90s） | Agent V2 工作流多轮模型调用+知识库检索，免费版排队 | 属上游耗时，正常等待（界面显示「思考中…」）；优化看 FastGPT 侧：模型节点统一 qwen-turbo、删无用工具节点 |
| 回答不看本批数据、答非所问 | FastGPT 丢弃入站 system 消息属正常契约 | v2.0 已把上下文注入 user 消息；若仍异常，检查本地代码是否为最新 |
| 回答仍要「file_path / 触发RPA」 | FastGPT 云端 Agent 提示词或知识库是旧版 | 工作台重写 Agent 系统提示词、重新上传本地 `RAG知识库/跨境对账规则文档.md` |

## 五、界面与启动

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Address already in use` | 8765 被旧进程占用 | `netstat -ano | findstr :8765` 找 PID，结束进程，或 `python app.py --port 8770` |
| 页面一直转圈 | 旧进程跑旧代码，或任务真在跑 | 重启服务（改代码/改 `.env` 后必须重启）；任务本身 15 分钟必出终态 |
| 控制台中文乱码 | Windows GBK 控制台 | 不影响运行（已内置编码降级）；日志文件 `data/logs/app.log` 是 UTF-8 正常可读 |
| Excel 下载 404「结果文件不存在」 | 输出目录被手动清理 | 重跑一次任务 |

## 七、日志在哪看（三处日志）

| 日志 | 位置 | 内容 |
|---|---|---|
| **应用日志** | `data/logs/app.log`（滚动：1MB × 5 个备份） | 启动配置体检 WARNING、上传/任务流转 INFO、`[CHAT]` 聊天请求 DEBUG 摘要、一切 ERROR 与完整堆栈 |
| **队列日志** | `data/logs/worker_console.log` | worker 子进程初始化、RQ 消费与 job 执行报错（含 rq 内部堆栈） |
| **任务日志** | `data/tasks/{task_id}/run.log`（每任务独立） | 7 步对账全流程：`[步骤n/7·xxx] 开始/完成`、读到多少行、差异构成、`[AI] 归因调用` 记录 |

**错误信息格式**：`2026-10-24 15:42:11 [ERROR] app: 聊天代理失败 task=xxx：原因` + `Traceback ...` 完整堆栈——ERROR 必带堆栈，按 task_id 可与 run.log 对上。

**两个兜底机制**（都会在 app.log 留 ERROR）：
- **15 分钟看门狗**：任务超时自动置 failed（`[看门狗]`），线程弃置
- **启动恢复**：服务重启时，遗留的 pending/running 任务一律置 failed（`[启动恢复]`），绝不假成功

**控制台**：应用日志同步打印到控制台（GBK 安全降级），排障时看 `data/logs/app.log` 更全。
