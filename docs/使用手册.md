# 使用手册（面向财务操作员）

浏览器打开即可对账：上传 5 份平台报表 → 自动双层对账 → 下载差异 Excel + AI 业务归因 + Agent 问答。

## 一、快速开始

**环境要求**：Windows + Python 3.10+（安装与配置详见《部署手册》）。

**三种启动方式任选其一**：

| 方式 | 操作 | 访问地址 |
|---|---|---|
| 本机（推荐） | 双击 `启动_本机.bat` | `http://127.0.0.1:8765` |
| 同事局域网访问 | 双击 `启动_局域网.bat` | `http://本机IP:8765`（IP 用 `ipconfig` 查） |
| 命令行 | 项目目录执行 `python app.py` | 同上 |

启动成功标志：控制台出现监听端口日志，浏览器能打开上传页。
**首次使用**：点击「一键填充示例数据」→ 开始对账 → 预期得到 **9 处差异**（订单侧 4 + 回款侧 5），用于验证环境是否正常。

## 二、界面总览

**上传页**
- 文件选择区：一次选齐 5 份 CSV；「已选文件列表」实时显示每份文件的类型识别结果；
- 「一键填充示例数据」：用内置样例体验完整流程；
- 「开始对账」：发起任务，页内显示任务状态。

**结果页**
- 7 步流水线：读取原始报表 → 订单标准化 → 结算标准化 → 第一层对账（订单结算）→ 第二层对账（结算回款）→ 导出差异Excel → 生成结果摘要，逐步变绿；
- 汇总卡片：总订单数、已结算数、差异数、AI 归因状态；
- 差异明细：「订单-结算差异」「结算-回款差异」两张表；
- 「下载对账差异 Excel」按钮；
- 页面下方「Agent 问答」聊天卡片（配置了 FastGPT 才显示）；
- 页面底部为任务历史，可回看往期结果。

## 三、操作步骤

1. 平台后台导出 5 份 CSV（命名与字段见第四节）。
2. 启动服务，打开上传页。
3. 选齐 5 份文件，核对「已选文件列表」5/5 且类型无误。
4. 点击「开始对账」，等待流水线走完（通常 1~3 分钟）。
5. 看汇总卡片差异数，逐条核对两张差异表。
6. 阅读「AI业务备注」列，验证每笔差异的业务原因。
7. 点击「下载对账差异 Excel」，按账期归档（规范见《SOP手册》第六节）。
8. 有疑问直接在「Agent 问答」里追问。

## 四、文件准备要求

### 命名规则（必须）
文件名需同时包含「平台词」与「类型词」：

| 文件 | 平台词 | 类型词 | 示例文件名 |
|---|---|---|---|
| 1 | 亚马逊 | 订单 | `亚马逊订单明细.csv` |
| 2 | 亚马逊 | 结算 | `亚马逊结算账单.csv` |
| 3 | Temu | 订单 | `Temu订单明细.csv` |
| 4 | Temu | 结算 | `Temu结算账单.csv` |
| 5 | 收款 | 流水 | `收款流水报表.csv` |

规则：**仅接受 `.csv` 后缀**；同类文件只能传一份；导出后不要用 Excel 二次编辑保存。

### 字段要求（表头，顺序可变）

**亚马逊订单明细.csv**
`order_id, sku, product_name, quantity, order_amount, currency, order_date, fulfillment, order_status, buyer_country`

**亚马逊结算账单.csv**
`settlement_id, order_id, product_sales, platform_commission, fba_fee, refund_amount, other_fee, total_settlement, currency, settlement_date`

**Temu订单明细.csv**
`order_id, sub_order_id, product_id, product_title, quantity, goods_amount, currency, create_time, order_status, logistics_no`

**Temu结算账单.csv**
`statement_no, order_id, sub_order_id, goods_amt, platform_service_fee, refund_amt, logistics_fee, actual_settlement, currency, settle_time`

**收款流水报表.csv**
`transaction_id, related_settlement, order_id, received_amount, fee, net_amount, currency, arrive_time, transaction_type, payment_channel`

> 不确定格式时，直接复制 `后台数据/` 内同名样例文件作模板，只替换数据行。

## 五、结果解读

### 9 种对账状态

**第一层：订单 ↔ 结算**

| 状态 | 含义 | 通常处置 |
|---|---|---|
| 结算正常 | 金额勾稽一致（订单额-各项费用=结算额） | 无需处理 |
| 结算金额差异 | 勾稽差超过 0.01 | 查费用项，真实异常走复核 |
| 已下单未结算 | 有订单无结算记录 | 账期内正常，超期需催 |
| 退款处理中 | 退款未完成 | 观察，下期复查 |
| 已退款结算 | 已按退款结算 | 核对退款金额 |

**第二层：结算 ↔ 回款**

| 状态 | 含义 | 通常处置 |
|---|---|---|
| 回款正常 | 结算总额=到账总额 | 无需处理 |
| 部分到账 | 回款少于结算（在途） | 账期内正常，挂观察 |
| 已结算未回款 | 完全没收到钱 | 超期即跟进，必要时申诉 |
| 回款金额差异 | 回款多于结算 | 真实异常，优先核查 |

### AI 业务备注

- 正常：AI 给出该行差异的业务解释（先脱敏再出网，原始账号金额不出本机）；
- 「未配置 AI Key，本次未归因」：`.env` 未配 `DASHSCOPE_API_KEY`，对账结果不受影响；
- 「AI服务已熔断，跳过分析」：AI 连续失败自动保护性跳过，新开任务即恢复；
- 「AI分析失败:…」：单次调用失败详情。
- 以上降级情况对账结果**始终有效**，备注可人工补写。

### 下载的 Excel

- 文件名：`对账差异_YYYYmmdd_HHMMSS.xlsx`；
- 双 Sheet：`订单结算差异`、`结算回款差异`，内容与页面一致。

## 六、Agent 问答使用

配置 `FASTGPT_BASE_URL / FASTGPT_API_KEY / FASTGPT_APP_ID` 后，结果页下方出现「Agent 问答」聊天卡片。

**适合问**：某笔差异为什么产生、扣点/退款/补贴规则、平台结算政策、下一步怎么处理。
**回答依据**：本批差异脱敏数据 + 内置对账规则知识库（RAG）。
**注意事项**：
- 回复耗时约 30~90 秒（多轮模型调用），界面显示「思考中…」属正常；
- 超过 180 秒无响应会提示服务不可用，稍后重试；
- AI 回答供参考，金额判断以对账结果与人工复核为准。

## 七、常见问题

| 问题 | 解决 |
|---|---|
| 上传被拒「无法识别的文件」 | 按第四节改文件名 |
| 上传被拒「重复上传」 | 同类文件删掉多余的 |
| 任务失败 | 看结果页「失败步骤」，查 `data/logs/app.log`，修复后重传；急则看《运维排障》 |
| 一直转圈/状态不动 | 15 分钟内看门狗自动给终态；刷新页面可立即判僵尸任务 |
| 页面提示 AI 未配置 | 编辑 `.env` 加 `DASHSCOPE_API_KEY` 并**重启服务** |
| 没有聊天窗口 | `.env` 配齐三个 FASTGPT 项并重启 |
| 聊天回复「服务暂不可用」 | 查网络/上游，看 `app.log` 的「聊天代理失败」 |
| 下载提示 404 | 输出文件被清理，重新跑一次任务 |
| 端口被占用 | `netstat -ano \| findstr :8765` 结束旧进程，或 `python app.py --port 8770` |
| 「一键填充示例数据」按钮报错 | `后台数据/` 被删，从项目原路径恢复（重启会自动回拷到 `data/sample/`） |

## 八、注意事项

1. **改 `.env` 后必须重启服务**，否则不生效。
2. **不要删除 `data/` 目录**——任务历史、日志、结果都在里面。
3. 项目根目录路径变更后首次启动会重新建 `data/`，历史列表可能指向旧路径，日常查询不受影响。
4. 局域网模式下任何能访问端口的人都能用，用完请关闭服务或限防火墙范围。
5. 控制台中文乱码不影响运行，日志以 `data/logs/app.log`（UTF-8）为准。
6. 更多故障处理见《运维排障》，操作流程与放行标准见《SOP手册》。
