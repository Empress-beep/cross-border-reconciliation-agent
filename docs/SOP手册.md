# SOP 手册：跨境多平台对账标准作业程序

适用对象：财务对账操作员、复核人（财务主管）、系统管理员。
适用范围：亚马逊 / Temu 平台「订单-结算-回款」日常与月结对账。

## 一、角色与职责

| 角色 | 职责 | RACI |
|---|---|---|
| 对账操作员 | 导出报表、上传任务、初核差异、归档结果 | 执行（R） |
| 复核人（财务主管） | 复核差异处置意见、放行/挂账/申诉决策 | 审批（A） |
| 系统管理员 | 服务启停、配置变更、日志与备份巡检 | 支持（C） |

## 二、总流程

```
S1 对账前准备 → S2 启动系统 → S3 上传报表 → S4 执行与结果检查
     → S5 AI 归因初核 → S6 差异分级处置 → S7 导出归档 → S8 期次确认
                                    ↘ 异常分支：E1~E5（见第四节）
```

标准耗时参考：样例数据全流程 1~3 分钟；真实账期数据（千行级）约 3~5 分钟，其中 AI 归因占大头。

## 三、标准操作步骤

### S1 对账前准备（操作员，账期截止后 1 个工作日内）
1. 确认账期：本次对账的起止日期、平台范围。
2. 从平台后台导出 **5 份 CSV**（文件名必须含关键字，详见《使用手册》第四节）：
   - 亚马逊订单明细、亚马逊结算账单、Temu订单明细、Temu结算账单、收款流水报表。
3. 检查导出时间范围是否与账期一致（**差异异常多数源于导错时间范围**）。
4. 检查上一期未决差异（未回款批次、申诉中订单）是否需要并入关注清单。
5. 导出后**不要用 Excel 二次编辑保存**（易破坏列名/编码），直接上传。

### S2 启动系统（操作员/管理员）
1. 双击 `启动_本机.bat`（本机）或 `启动_局域网.bat`（同事访问）。
2. 浏览器访问 `http://127.0.0.1:8765`。
3. 健康检查：控制台启动日志**无 ERROR**；若有黄色 WARNING（AI Key 未配置等）记录并按第五节处置。
4. 改过 `.env` 必须重启服务才生效。

### S3 上传报表（操作员）
1. 上传页勾选 5 份文件 → 核对「已选文件列表」5/5、类型识别无误。
2. 点击开始对账，观察 7 步流水线逐项变绿：读取原始报表 → 订单标准化 → 结算标准化 → 第一层对账 → 第二层对账 → 导出差异Excel → 生成结果摘要。
3. 任一步变红 → 转 **E2 异常流程**。

### S4 执行与结果检查（操作员）
1. 核对汇总卡片：总订单数、已结算数、差异数。
2. **基线核对**：标准样例账期预期 **9 处差异（订单侧 4 + 回款侧 5）**。明显偏离时按 **E4** 处置，不得直接进入放行。
3. 快速扫两张差异表：订单结算差异、结算回款差异。

### S5 AI 归因初核（操作员）
1. 逐条阅读「AI业务备注」列，结合订单号/结算单号在源表验证。
2. 识别降级表现：
   - 备注为「未配置 AI Key，本次未归因」（琥珀色）→ 本次仅规则对账，AI 补跑见 E3；
   - 备注为「AI服务已熔断，跳过分析」→ 同 E3；
   - 备注为「AI分析失败:…」→ 同 E3。
3. AI 备注**只作参考，不作放行依据**——金额判断以规则对账结果与人工复核为准。

### S6 差异分级处置（操作员初判 → 复核人审批）

| 级别 | 判定 | 处置 | 责任人 |
|---|---|---|---|
| L1 正常在途 | 「部分到账」且账期未截止 | 挂观察，下期自动覆盖 | 操作员记录 |
| L2 需跟进 | 「已下单未结算」「退款处理中」超账期 | 催结算/查退款进度，登记跟进表 | 操作员 |
| L3 真实异常 | 「结算金额差异」「回款金额差异」「已结算未回款」 | 出具差异说明 → 复核人审批 → 平台申诉或挂账 | 复核人 |

### S7 导出归档（操作员）
1. 下载 `对账差异_日期_时间.xlsx`（双 Sheet：订单结算差异 / 结算回款差异）。
2. 按归档规范存入账期目录（见第六节），同时保留系统内 `data/tasks/{任务ID}/` 原始结果。
3. L3 差异同步登记差异台账（Excel 或内部系统）。

### S8 期次确认（复核人）
按第九节《月结复核清单》逐项打勾 → 签字放行 → 本期对账关闭。

## 四、异常处理 SOP

| 编号 | 现象 | 处置步骤 |
|---|---|---|
| E1 | 上传被拒（无法识别/重复/非CSV） | ① 文件名按规范改名（含 亚马逊\|Temu\|收款 + 订单\|结算\|流水）② 每类只选一份 ③ 必须 `.csv` 后缀 |
| E2 | 任务失败 | ① 记录失败步骤（结果页「失败步骤」字段）② 查 `data/logs/app.log` 对应错误 ③ 修复后重新上传重跑 ④ 处理不了转系统管理员，15 分钟自动判超时无需干等 |
| E3 | AI 归因降级 | ① 对账结果有效，**不重跑整单** ② 配好 `DASHSCOPE_API_KEY` 后**新开任务**验证 AI 恢复 ③ 本期备注由人工补写 |
| E4 | 差异数与预期严重不符 | ① 首查导出时间范围是否对准账期 ② 核对 5 份文件是否为同一批次导出 ③ 查源表是否有空文件/重复行 ④ 排除后联系复核人共同研判，**禁止跳过直接放行** |
| E5 | 服务无法启动 | ① `Address already in use`：`netstat -ano \| findstr :8765` 找 PID 结束旧进程 ② 改用 `python app.py --port 8770` ③ 仍失败转《运维排障》第四节 |

## 五、配置变更 SOP（系统管理员）

1. 变更前：说明变更内容与影响（如换 AI Key、改端口、配 FastGPT）。
2. 变更中：编辑 `.env`；**改完必须重启服务**。
3. 变更后：跑一遍示例任务验证；启动日志无新 ERROR；在变更记录表登记（日期/人/内容/回滚方式）。
4. 回滚：保留旧 `.env` 副本，随时可还原重启。

## 六、数据归档与保留 SOP

| 项 | 规范 |
|---|---|
| 归档目录 | `账期归档/{YYYY-MM}/{平台}/`，存放下载的差异 Excel 与 5 份源 CSV |
| 命名 | 沿用系统文件名 `对账差异_YYYYmmdd_HHMMSS.xlsx`，源表加账期前缀 |
| 系统内数据 | `data/tasks/{任务ID}/` 每任务独立目录，**禁止手工删除**（页面历史与追溯依赖它） |
| 保留期 | 按公司财务档案制度执行（参考《会计档案管理办法》，建议不低于 10 年） |
| 备份 | 管理员每周将 `data/` 与账期归档目录打包备份至异处（网盘/另一块盘）；备份后抽查可解压 |

## 七、系统巡检 SOP

| 频率 | 检查项 | 通过标准 |
|---|---|---|
| 每日启动 | 启动日志、示例任务 | 无 ERROR；示例任务 success |
| 每周 | 日志滚动、磁盘空间、备份 | `app.log` 未超限；磁盘余量 >20%；备份存在 |
| 每月 | 任务历史清理策略 | 超保留期且已归档的任务目录按制度清理 |
| 每次变更后 | 功能冒烟 | 上传→对账→下载→问答全通 |

## 八、应急预案

| 场景 | 预案 |
|---|---|
| AI 服务整体不可用 | 对账不受影响（降级设计）；本期人工归因；按 E3 恢复验证 |
| 服务崩溃/断电 | 重启 `启动_本机.bat`；未完成任务显示失败，重新上传即重跑；历史任务不受影响 |
| 疑似数据丢失 | 立即停止对 `data/` 的一切写入；从最近周备份恢复；核对任务历史列表与归档目录 |
| 局域网误暴露公网 | 立即关闭服务；改用本机模式；排查防火墙 8765 放行范围 |
| 上班高峰拥堵 | 任务本就串行排队，无需干预；若需并行等中期改造（任务表+并发队列） |

## 九、月结复核清单（复核人逐项打勾）

- [ ] 5 份源报表时间范围与账期一致，且为同批导出
- [ ] 流水线 7 步全绿，任务状态 success
- [ ] 差异数量与预期基线偏离已解释（E4 已闭环）
- [ ] 每条 L3 真实异常均有：差异说明 + 业务原因 + 处置意见（申诉/挂账/催收）
- [ ] AI 降级行已人工补写备注（如有）
- [ ] 差异 Excel 已下载并归档至账期目录，系统任务历史可查
- [ ] 上期未决事项（在途回款、申诉中）状态已更新
- [ ] 复核结论：□ 放行 □ 有条件放行（列遗留项）□ 退回重对
