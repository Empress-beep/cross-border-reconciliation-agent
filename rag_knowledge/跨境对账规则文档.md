# 跨境电商多平台对账业务规则

## 1、对账业务概述

本业务针对跨境电商多平台订单开展自动对账。参与数据源共 5 份 CSV 文件：Temu 订单明细、Temu 结算账单、亚马逊订单明细、亚马逊结算账单、收款流水报表。收款流水同时覆盖 Temu（派安盈渠道）与亚马逊（连连国际渠道），退款退回走 PayPal。

对账核心目标：校验「订单销售额」「平台各类扣费」「结算金额」「实际收款」四者逻辑一致；标记金额差异、订单缺失、流水孤儿、退款异常四类问题；输出对账结果 Excel，并支持 AI 差异化分析（ai_switch 开关）。

> 关键概念：
> - 订单金额：商品售价 × 数量（Temu 为 goods_amount，亚马逊为 order_amount）
> - 结算金额：平台扣除佣金/物流/FBA/退款/其他费用后，应结给收款的金额
> - 实际收款：收款流水中的 received_amount（对应结算金额）
> - 净到账：收款金额扣掉收款渠道手续费后的最终入账（net_amount）

## 2、五份数据源文件与字段定义

### 2.1 Temu 订单明细（Temu订单明细.csv）
| 字段 | 含义 |
|----|----|
| order_id | Temu 订单号，对账主键 |
| sub_order_id | 子单号，一笔订单可含多个子单 |
| product_id / product_title | 商品 ID 与名称 |
| quantity | 数量 |
| goods_amount | 商品金额 |
| currency | 币种（USD） |
| create_time | 下单时间 |
| order_status | 订单状态：已签收 / 运输中 / 退款中 / 已发货 / 待发货 |
| logistics_no | 物流单号，未发货为空 |

### 2.2 Temu 结算账单（Temu结算账单.csv）
| 字段 | 含义 |
|----|----|
| statement_no | 结算单号，对账关联键（TEMU-ST-xxxx） |
| order_id | 对应 Temu 订单号 |
| sub_order_id | 子单号 |
| goods_amt | 商品金额 |
| platform_service_fee | 平台服务费（佣金） |
| refund_amt | 退款金额，无退款为 0 |
| logistics_fee | 物流费 |
| actual_settlement | 实际结算金额 |
| currency / settle_time | 币种 / 结算时间 |

### 2.3 亚马逊订单明细（亚马逊订单明细.csv）
| 字段 | 含义 |
|----|----|
| order_id | 亚马逊订单号，对账主键（AMZ-xxxx） |
| sku / product_name | 商品信息 |
| quantity | 数量 |
| order_amount | 订单金额 |
| currency / order_date | 币种 / 下单时间 |
| fulfillment | FBA（亚马逊物流）/ FBM（卖家自发货） |
| order_status | Shipped / Refunded / Pending |
| buyer_country | 买家国家 |

### 2.4 亚马逊结算账单（亚马逊结算账单.csv）
| 字段 | 含义 |
|----|----|
| settlement_id | 结算单号，对账关联键（AMZ-SET-xxxx） |
| order_id | 对应亚马逊订单号 |
| product_sales | 商品销售额 |
| platform_commission | 平台佣金 |
| fba_fee | FBA 仓储物流费（FBM 订单为 0） |
| refund_amount | 退款金额，无退款为 0 |
| other_fee | 其他费用（如广告/杂费） |
| total_settlement | 结算总额 |
| currency / settlement_date | 币种 / 结算时间 |

### 2.5 收款流水报表（收款流水报表.csv）
| 字段 | 含义 |
|----|----|
| transaction_id | 收款流水号 |
| related_settlement | 关联结算单号（Temu 的 statement_no 或亚马逊的 settlement_id），跨表关联键 |
| order_id | 关联订单号 |
| received_amount | 收款金额（对应结算金额，退款退回为负数） |
| fee | 收款渠道手续费 |
| net_amount | 净到账金额 |
| currency / arrive_time | 币种 / 到账时间 |
| transaction_type | 结算回款 / 退款退回 |
| payment_channel | 收款渠道：连连国际（亚马逊）、派安盈（Temu）、PayPal（退款） |

## 3、核心计算公式（已用真实数据验证）

### 3.1 Temu 结算公式
```
actual_settlement = goods_amt − platform_service_fee − refund_amt − logistics_fee
```
验证：TEMU-901001 → 12.85 − 1.29 − 0 − 1.80 = 9.76 ✓（与账单一致）

### 3.2 亚马逊结算公式
```
total_settlement = product_sales − platform_commission − fba_fee − refund_amount − other_fee
```
验证：AMZ-20260901-001 → 45.99 − 6.90 − 4.25 − 0 − 0.30 = 34.54 ✓
退款单：AMZ-20260902-004 → 29.97 − 4.50 − 6.30 − 29.97 − 0 = −10.80 ✓（全额退款结算为负）

### 3.3 收款净到账公式
```
net_amount = received_amount − fee
```
验证：PAY-20260906-001 → 34.54 − 1.20 = 33.34 ✓

## 4、跨表关联关系（主键映射）

| 关联 | 关联键 | 校验内容 |
|----|----|----|
| Temu订单明细 → Temu结算账单 | order_id | goods_amount 应与 goods_amt 一致 |
| Temu结算账单 → 收款流水 | statement_no = related_settlement | actual_settlement 应与 received_amount 一致 |
| 亚马逊订单明细 → 亚马逊结算账单 | order_id | order_amount 应与 product_sales 一致 |
| 亚马逊结算账单 → 收款流水 | settlement_id = related_settlement | total_settlement 应与 received_amount 一致 |

## 5、对账校验流程

1. 读取 5 份 CSV，按关联键建立订单、结算、收款三层映射；
2. 按第 3 节公式复算每个结算单的结算金额，与账单列对比；
3. 用结算金额关联收款流水，核对实际收款是否到账；
4. 输出三份文件：全部结果、差异明细、运行日志。

## 6、异常类型判定

1. **金额差异**：复算结算金额与账单结算金额不一致，或结算金额与收款流水 received_amount 不一致；
2. **订单缺失（已结算未到账）**：结算账单存在该订单，但收款流水找不到对应记录（real 数据中 TEMU-902004、TEMU-904008、TEMU-904007、AMZ-20260904-008 属此类）；
3. **流水孤儿**：收款流水存在，但找不到对应结算单/订单；
4. **退款异常**：订单 status=退款中 或退款金额>0，但收款流水无对应退款退回记录。

## 7、退款订单处理

1. 退款金额参与扣减计算（refund_amount / refund_amt）；
2. 全额退款结算金额为负（如 AMZ-20260902-004 = −10.80）；
3. 退款退回走 PayPal 渠道，transaction_type=退款退回，received_amount 为负数；
4. 退款金额>0 但无退款流水 → 标记退款异常。

## 8、收款渠道区分

- 亚马逊结算回款 → 连连国际
- Temu 结算回款 → 派安盈
- 退款退回 → PayPal
> 对账时按 related_settlement 关联，不按渠道名称判断业务。

## 9、AI 差异化分析开关（ai_switch 参数）

- ai_switch = "1"：开启 AI 分析。对差异明细逐条调用大模型，推测差异原因（佣金波动、退款滞后、汇率差、手续费、费用漏记），输出建议追加到 ai_analysis_suggest 列；
- ai_switch = "0"：仅做数值对账，不调用大模型。

## 10、Agent 调用约束（给 FastGPT RAG 用）

1. 用户提出对账需求，Agent 不要自己计算对账结果；
2. 必须提取两个入参：file_path（5 份 CSV 所在文件夹路径）、ai_switch（"1"/"0"）；
3. 调用外部 HTTP 工具【触发影刀对账】POST 下发参数；
4. 工具成功后回复用户：对账任务已提交，请查看 output 目录结果文件；
5. 用户未给路径时，先反问获取数据源文件夹路径。

## 11、常见业务异常参考（RAG 召回用）

1. 汇率波动：平台美元结算与收款币种转换产生小额差额，属可接受现象；
2. 扣费/结算时间错位：当期结算未在当期收款流水体现，属正常时滞，不判为错误；
3. 部分退款多次：容易造成计算偏差，需按退款累计核对；
4. 广告/其他费用统一账单扣费，无法匹配单订单粒度。
